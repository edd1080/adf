# ADF v0.1.0 Implementation Plan

> **For Codex/OpenCode:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Use `test-driven-development` or the adapted `tdd` skill for every behavioral slice. Do not commit unless the user explicitly authorizes that specific commit.

**Goal:** Build a locally testable `adf` CLI that safely bootstraps an empty or existing repository into the approved ADF harness, configures Spec Kit for Codex and OpenCode, and routes the first agent session into guided project intake.

**Architecture:** A TypeScript CLI owns deterministic filesystem work and delegates Spec Kit operations through a capability-detecting adapter. Templates and adapted skills ship inside the package; the generated repository owns operational state in `.harness/`, feature state in `specs/`, and shared agent behavior in `AGENTS.md` plus `.agents/skills/`. All mutations are preceded by a plan and applied transactionally.

**Tech Stack:** Node.js 20+, TypeScript ESM, npm, Commander, `@clack/prompts`, Zod, YAML, Execa, Vitest, ESLint, Prettier.

---

## 0. Execution rules

1. Execute tasks in order unless a failing prerequisite forces re-planning.
2. Use temporary directories for filesystem tests; never run clean-room tests against the framework repository itself.
3. Every implementation step follows red → green → refactor.
4. Run the focused test after every change and the complete suite at each task boundary.
5. Record verification commands and results in `docs/verification/v0.1.0.md`.
6. Treat commit steps as optional human checkpoints. Show the proposed command; execute it only after explicit approval.
7. No npm publish, GitHub repository creation, tag, push, or Spec Kit catalog submission is authorized by this plan.
8. Before execution, create a dedicated Git repository or worktree for ADF. The current projectless output directory is documentation, not the implementation repository.
